## 三、发现的问题与修复清单

### 3.1 认证与权限

| 问题 | 根因 | 修复方案 |
|---|---|---|
| 无 Token 访问受保护接口返回 403 而非 401 | SecurityConfig 未配置未认证入口点 | 添加 AuthenticationEntryPoint 返回 401 |
| 密码错误返回 HTTP 400 | 参数校验异常被当作业务错误处理 | 区分 BindException 与业务异常 |
| 班线购票未认证访问返回 500 | 权限规则顺序导致公开规则覆盖认证规则 | 调整 SecurityConfig 权限顺序 |
| JWT 密钥长度不足 256 位 | application.yml 中 jwt.secret 过短 | 更新为 32 字节强密钥 |

### 3.2 订单与支付

| 问题 | 根因 | 修复方案 |
|---|---|---|
| 优惠券 ID 语义不一致 | 前端同时使用 couponId 与 userCouponId | 统一使用 UserCoupon.id，新增 UserCouponVO |
| 评价后司机评分未更新 | OrderServiceImpl.review 未触发司机评分重算 | 添加司机平均评分计算逻辑 |
| 订单取消后司机状态未恢复 | cancel 方法缺少 driver.status 更新 | 取消后恢复司机为在线状态 |
| 重复支付未拦截 | pay 方法未检查订单已支付状态 | 添加已支付检查并返回 PAY_FAILED |
| 支付回调接口需要认证 | SecurityConfig 将 /api/payment/** 配置为认证 | 单独开放 /api/payment/callback |
| 优惠券重复领取错误码硬编码 | CouponServiceImpl 直接抛出 3005 | 在 ErrorCode 中新增 COUPON_ALREADY_CLAIMED(5101) |
| 支付幂等键未贯通前端 | Payment.vue / payment.js 未生成和传递幂等键 | 前端生成 UUID，后端按 orderId:userId 兜底 |
| 并发支付默认幂等键不收敛 | 默认幂等键包含时间戳，分布式锁失效 | 默认幂等键统一为 pay:idempotent:orderId:userId |
| 并发下多司机可同时接单 | accept 方法缺少分布式锁，且锁在事务提交前释放 | 引入 Redisson 订单级锁 + TransactionTemplate 编程式事务 |
| 并发下可重复创建支付记录 | pay 方法缺少分布式锁，且锁在事务提交前释放 | 引入 Redisson 订单级锁 + TransactionTemplate 编程式事务 |
| 订单状态变更未实时推送 | OrderServiceImpl 未调用 WebSocket 推送 | 在 accept/arrive/start/complete 后调用 OrderTrackingServer.pushOrderUpdate |

### 3.3 测试与数据

| 问题 | 根因 | 修复方案 |
|---|---|---|

## 四、优化建议与策略规划

### 4.1 测试基础设施（高优先级）

**建议 1：建立端到端（E2E）测试流水线**
- 使用 Playwright 覆盖乘客下单、司机接单、支付评价的完整流程。
- 在 CI 中集成 E2E 测试，每次提交流程跑一次。
- 设定测试数据隔离方案，避免生产数据污染。

**建议 2：完善核心业务流程测试**
- 补充风控规则测试（取消率、投诉率、风险画像）。
- 增加并发场景测试（同一订单多司机抢单、重复支付并发）。
- 补充 WebSocket 实时消息测试。

**建议 3：测试数据可重复执行机制**
- 每个测试脚本执行前后自动清理自身产生的数据。
- 引入事务回滚或独立测试数据库，避免测试间相互影响。

### 4.2 安全与权限（高优先级）

**建议 4：安全与权限专项审查**
- 引入 Spring Security 方法级注解（@PreAuthorize）替代部分 URL 权限配置。
- 对敏感操作（取消订单、退款、修改司机状态）增加操作日志审计。
- 定期进行 JWT 密钥轮换机制设计。

**建议 5：支付与风控加固**
- 支付接口增加幂等键校验与分布式锁。
- 风控规则配置化，支持动态调整阈值。
- 增加异常订单自动告警（长时间未支付、频繁取消等）。

### 4.3 性能优化（中优先级）

**建议 6：前端性能持续优化**
- 继续拆分大型 vendor chunk，对 Element Plus 进行按需引入。
- 图片资源使用 WebP 格式并接入 CDN。
- 关键页面开启路由懒加载与组件级 keep-alive。

**建议 7：后端性能持续优化**
- 对管理员大屏统计接口增加缓存（Redis）。
- 对订单列表、司机附近订单等接口进行慢查询监控。
- 引入分页与游标机制，避免大数据量查询。

### 4.4 文档与交付（中优先级）

**建议 8：API 文档一致性**
- 统一接口路径前缀与命名规范。
- 补充 Knife4j 注解，确保所有公开接口均有文档。
- 维护接口变更日志，前后端版本对齐。

**建议 9：风险适配与回滚策略**
- 生产发布前制定灰度方案。
- 对数据库索引变更、JWT 密钥变更等操作提供回滚脚本。
- 建立核心接口监控与告警。
