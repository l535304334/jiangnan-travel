## 一、功能完成度总览

### 1.1 已完成（基础可用）
| 功能 | 完成度 | 质量 |
|---|---|---|
| 用户注册/登录 | 90% | 高 |
| 订单创建/列表/详情 | 85% | 中高 |
| 价格预估 | 80% | 中高（阶梯计价完整） |
| 高德路线规划 | 85% | 中高（3策略+fallback） |
| AI客服（江小游） | 80% | 中（SSE流式可用，理解力待优化） |

### 1.2 完成质量不足（需重构）
| 功能 | 当前状态 | 目标 |
|---|---|---|
| 司机端首页/收入/个人 | 全假数据 | 对接真实API |
| 优惠券使用 | 只能领取，无法使用 | 下单时选择优惠券 |
| 行程追踪 | 无实时位置 | WebSocket实时位置 |
| 地址搜索 | 仅20个预设地标 | 高德POI搜索 |
| 首页布局 | 文旅内容过多 | 聚焦出行功能 |

## 二、功能模块依赖关系

```
消息通知 ←─┐
           │ 依赖
订单系统 ←─┘
  ├── 计价引擎
  ├── 优惠券系统 ←── 活动系统
  ├── VIP会员（影响计价）
  └── 支付系统 → 发票系统

AI客服 ←── 文旅数据
数据可视化 ←── 订单/用户/司机数据
```

## 三、开发优先级矩阵

| 象限 | 功能 | 原因 |
|---|---|---|
| 高价值·低复杂度 | 优惠券下单使用、消息通知、司机真实API对接 | 快速交付高感知功能 |
| 高价值·高复杂度 | 活动页+VIP、高德POI搜索 | 核心差异化功能 |
| 低价值·低复杂度 | 关于我们优化、文旅地标独立页 | 锦上添花 |
| 低价值·高复杂度 | 支付集成、多语言 | 长期规划 |
