## 3 分钟版本

各位老师好。我介绍的是我独立设计开发的一个网约车调度系统——**江南出行**。

这个项目的核心是一个问题：**多乘客同时下单、多司机在线时，怎么保证派单不出错**——不会一个司机被分给两个人，也不会一个订单没人接。

我做了三个关键设计。

**第一，状态机**。订单从创建、支付、派单、接单、行程、完成，总共10个状态。我没有用 if-else 散落在各处，而是把所有合法流转写在一张表里。任何一个状态变更都先检查是否合法。18个单元测试覆盖了所有合法和非法的路径——新增状态只改一个文件。

**第二，并发调度**。这是最难的部分。50个订单同时抢20个司机，怎么保证不重复？我用Redis实现了二阶分布式锁——先锁订单防重复派，再 tryLock 司机防重复分配。拿不到锁的自动 fallback 下一位候选人。锁顺序100%统一，数学上保证无死锁。压测100订单、20司机，零重复分配、零丢失。

**第三，评分收敛**。如果永远把订单给评分最高的司机，其他人永远拿不到——这叫正反馈循环。我加了一个动态学习层：拒单扣分、接单加分、10分钟衰减回到正常。5轮派单后成功率从50%升到70%，系统自己收敛。

整个系统全栈实现——Spring Boot 后端、Vue3 前端、MySQL + Redis。事件溯源记录所有状态变更，外加三层可观测性。代码量不大，核心调度逻辑不到300行，但涵盖了几个我认为很重要的分布式系统设计点。

谢谢。

## 5 分钟版本

各位老师好。我今天介绍的项目是江南出行——一个网约车智慧调度系统。

**（背景 — 30秒）**

这个项目是毕业实习期间做的。公司需要一套完整的出行平台，覆盖乘客、司机、管理后台三端。但我个人在开发过程中，把精力集中在了一个我认为最有工程挑战的问题上：**调度系统**。

为什么选调度？因为网约车调度不是"找到一个司机就派过去"这么简单。在真实场景中——50个乘客同时下单、20个司机在线——你需要在几百毫秒内完成匹配，而且必须保证零错误。在滴滴、Uber这种规模下，一个重复分配就可能造成真实的事故。

**（架构 — 1分钟）**

系统架构分四层。**业务层**负责订单生命周期——创建、支付、取消、评价。**调度层**是核心——拿到 PAID 状态的订单、根据评分引擎排序所有在线司机、用分布式锁分配。**学习层**在评分之上做动态调整——司机行为反馈、自动收敛。**观测层**做指标统计、异常检测、健康评分。

技术栈是 Spring Boot + MyBatis-Plus + Redis Redisson + MySQL，前端 Vue3 + Element Plus。前后端分离，三端鉴权。

**（调度设计 — 1.5分钟）**

调度的核心挑战是并发控制。我设计了一个二阶分布式锁方案。

先说问题：如果订单A和订单B同时计算出来"司机3是最优选择"，怎么办？单机环境下 synchronized 就够了，但分布式环境下需要跨JVM互斥。

我的方案：第一层，订单锁——`order:dispatch:{orderId}`。这是排他锁，保证同一个订单不被两个请求同时派单。第二层，司机锁——`driver:lock:{driverId}`。这一层用的是 tryLock，500 毫秒超时。为什么是 tryLock？因为如果死等，一个被抢走的司机会卡住整个派单链路。tryLock 失败说明司机已被其他订单锁定，直接跳过，尝试下一位候选。

这里有一个关键细节：**锁顺序100%统一**——永远是先 order 锁再 driver 锁。这是死锁预防的经典条件，不存在 A 等 B、B 等 A 的情况。

然后是评分引擎。静态评分有四个维度：距离40%、评分30%、空闲时间20%、拒单惩罚10%。但静态评分有个致命问题——正反馈循环。如果你排名高，你就永远拿订单；排名低就永远拿不到。系统会越来越不稳定。

我加了一层动态学习：司机每次接单 +5分，拒单 -10分。但这个分数不是永久的——它有一个10分钟的半衰期，自动向0回归。这样拒单多的司机排名自动下降，空闲久的被推上来。整个过程不需要人工干预。压测验证了收敛性：5轮派单后成功率从50%升到70%，评分波动减半。

**（数据设计 — 30秒）**

所有状态变更都记录在 order_event 表里——不是操作日志，是轻量级事件溯源。12种事件类型覆盖全流程。一条SQL就能回溯任意订单的完整生命周期。

**（AI协作 — 30秒）**

这个项目还有一个特色：我从需求分析到测试全部使用AI辅助——Claude Code。AI参与了约60%的工作——主要是样板代码、测试脚本、文档生成。但所有关键决策——锁设计、状态机设计、评分收敛——都是我做的。我还建立了20条规则约束AI的行为。这是一个"人类主导+AI增强"的实践。

**（总结 — 30秒）**

总结一下：这个项目不是一个CRUD demo。它的调度层——二阶分布式锁和可收敛评分引擎——展示了分布式系统和算法设计能力。状态机形式化和事件溯源展示了软件工程素养。AI辅助开发实践是加分项。

核心代码不到300行，但每个设计决策都有明确的工程理由。谢谢各位老师。
