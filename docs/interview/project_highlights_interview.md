# 项目亮点强化版（面试用）

> 每个亮点：技术点 → 为什么重要 → 项目中如何体现

---

## 亮点 1：高并发派单一致性保障（二阶分布式锁）

**技术点**：基于 Redis Redisson 的二阶分布式锁 + tryLock fallback 机制。

**为什么重要**：分布式并发是后端工程师的核心能力分水岭。单机 synchronized 人人会写，但跨 JVM/跨请求的互斥需要理解分布式锁的语义——锁顺序、超时、ABA 问题、死锁预防。

**项目中如何体现**：
- 100 订单 × 20 司机并发压测：零重复分配、零死锁
- 锁顺序 100% 统一（order → driver）→ 数学上无死锁
- tryLock 500ms 超时 + fallback 候选 → 高碰撞下自动降级
- 加锁后重读 DB 防 ABA

---

## 亮点 2：可收敛的动态调度评分引擎

**技术点**：静态加权评分 + 反馈学习 + 指数时间衰减。

**为什么重要**：评分系统不是"排序"——正反馈循环是真实存在的系统稳定性问题。这个概念和 PageRank 的阻尼因子、TCP 拥塞控制的 AIMD 是同源的工程思想。

**项目中如何体现**：
- 4 维静态评分（距离/评分/空闲/拒单）+ 动态 modifier 叠加
- 接单加分、拒单扣分、10 分钟半衰期衰减
- 5 轮派单后成功率 ↑ 20pp，评分波动 ↓ 50%
- ScoringEngine 接口化 → 可插拔替换为 ML 模型

---

## 亮点 3：形式化订单状态机

**技术点**：枚举 + 流转表集中管理 10 状态 15+ 路径。

**为什么重要**：if-else 状态管理无法审计、无法测试、无法扩展。形式化状态机是软件工程的基础——可穷举、可验证、可扩展。

**项目中如何体现**：
- `Map<OrderStatus, Set<OrderStatus>>` 一张表说清楚所有合法路径
- `guardTransition()` 一行代码防御全系统非法流转
- 18 个单元测试覆盖全部路径，30 秒跑完
- 新增状态只改 1 个文件

---

## 亮点 4：事件溯源式数据设计

**技术点**：order_event 表 + 12 种事件类型 + 全链路时间戳记录。

**为什么重要**：操作日志和事件溯源是两种设计哲学。操作日志是"谁做了什么"，事件溯源是"系统经历了什么状态变化"。后者可以直接回答统计问题，且为 CQRS 铺路。

**项目中如何体现**：
- 12 种事件类型覆盖从 CREATED 到 REVIEWED 全流程
- 一条 SQL 回溯任意订单完整生命周期
- 统计"系统派单 vs 司机接单"比例无需联表
- 为未来 Kafka 异步消费打下基础

---

## 亮点 5：三层可观测性体系

**技术点**：Metrics（数据采集）+ Health（综合评分）+ Anomaly（异常检测）。

**为什么重要**：可观测性不是"有日志"。真正的运维体系应该让不同角色看到不同视图——值班看面板、发布看评分、排查看异常。

**项目中如何体现**：
- Metrics：成功率、延迟、司机负载分布（线程安全 LongAdder）
- Health：加权公式 S/A/B/C/D 五级评分
- Anomaly：连续拒单≥5、失败≥3、锁竞争≥10、波动>30 自动标记
- 4 个 REST 端点实时查询

---

## 亮点 6：AI 辅助全流程开发实践

**技术点**：Claude Code + Agent 体系 + MCP 工具链 + 20 条行为约束规则。

**为什么重要**：2025-2026 年 AI 辅助开发已成为软件工程的必答题。导师极大概率会问"AI 怎么用的"。关键不是"AI帮我写了代码"，而是"我做了决策，AI帮我执行"。

**项目中如何体现**：
- AI 参与度约 60%（样板代码、测试、文档）
- 人类主导 40%（架构决策、并发安全、评分收敛）
- 建立了 20 条规则约束 AI 行为（CLAUDE.md）
- 效率提升：代码 2.5×、测试 2×、文档 50×
- 核心 Bug（ABA 竞态）由人类发现——验证"关键逻辑不能全交AI"

---

## 亮点 7：四层架构与模块解耦

**技术点**：业务层 → 调度层 → 学习层 → 观测层，接口隔离。

**为什么重要**：架构不是"分了几层"，而是"变化点在哪里"。出行调度系统的变化点在评分策略——如果策略代码散落各处，每次调整都是全量回归。

**项目中如何体现**：
- ScoringEngine 接口 → 2 个实现（静态 + 动态），改一行注入即可切换
- 无循环依赖（所有依赖方向统一）
- 新增状态 1 文件 1 行；替换策略 1 文件 1 行

---

## 亮点 8：完整工程规范

**技术点**：统一返回结构、全局异常处理、JWT 三端鉴权、数据库 27 表设计。

**为什么重要**：研究生复试中，导师关注的不是你"会不会写代码"，而是你"有没有工程意识"——异常处理、权限控制、数据库设计规范。

**项目中如何体现**：
- `Result<T>` 统一 API 返回 + `GlobalExceptionHandler` 全局异常处理
- Spring Security + JWT 乘客/司机/管理员三端鉴权
- 27 张表含索引、迁移脚本、种子数据、测试账号
- 7 个 SQL 迁移脚本按版本管理
