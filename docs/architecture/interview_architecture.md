## 五、订单状态流转图

> 10 个状态 + 15 条合法流转路径，集中在 OrderStatus 枚举的 ALLOWED_TRANSITIONS 表中。

```
                    ┌──────────┐
                    │ CREATED  │ ← 乘客下单
                    └────┬─────┘
                         │ 支付成功
                    ┌────▼─────┐
        ┌───────────│   PAID   │───────────┐
        │           └────┬─────┘           │
        │ 系统派单        │ 系统派单         │
        │ (新流程)        │ (旧流程)         │
┌───────▼──────┐   ┌────▼─────────┐   ┌───▼──────────┐
│DRIVER_ASSIGNED│   │   ASSIGNED   │   │  CANCELLED   │← 乘客取消
└───────┬──────┘   └────┬─────────┘   └──────────────┘
        │ 司机确认接单     │
        │           │
        └─────┬─────┘
              │ 司机到达上车点
       ┌──────▼───────┐
       │DRIVER_ARRIVED│
       └──────┬───────┘
              │ 开始行程
       ┌──────▼──────┐
       │ TRIP_STARTED│
       └──────┬──────┘
              │ 行程完成
       ┌──────▼──────┐
       │  COMPLETED  │
       └──────┬──────┘
              │ 支付完成
       ┌──────▼──────┐
       │  PAID_FINAL │
       └──────┬──────┘
              │ 乘客评价
       ┌──────▼──────┐
       │  REVIEWED   │ → 订单结束
       └─────────────┘
```

**关键流转规则**（guardTransition 校验）：
- CREATED → PAID → DRIVER_ASSIGNED/ASSIGNED → DRIVER_ARRIVED → TRIP_STARTED → COMPLETED → PAID_FINAL → REVIEWED
- 任意非终态 → CANCELLED（需满足取消条件）
- 非法流转直接抛异常（如 CREATED → COMPLETED）

**事件记录**：每次状态变更写入 t_order_event，覆盖 12 种事件类型。

## 六、分布式锁详细流程图

> 二阶锁：order lock → driver tryLock，保证零重复分配。

```
订单 A 请求派单                    订单 B 请求派单（同一司机）
     │                                   │
     ▼                                   ▼
┌────────────────────┐            ┌────────────────────┐
│ Phase 1:            │            │ Phase 1:            │
│ lock(order:dispatch │  ← 阻塞 →  │ lock(order:dispatch │
│       :orderIdA)    │            │       :orderIdB)    │
└────────┬───────────┘            └────────┬───────────┘
         │ 成功获取                         │ 成功获取（A 释放后）
         ▼                                 ▼
┌────────────────────┐            ┌────────────────────┐
│ findCandidates()   │            │ findCandidates()   │
│ 选中司机 [3, 7, 5] │            │ 选中司机 [3, 7, 5] │
└────────┬───────────┘            └────────┬───────────┘
         ▼                                 ▼
┌────────────────────┐            ┌────────────────────┐
│ Phase 2:            │            │ Phase 2:            │
│ tryLock(driver:     │            │ tryLock(driver:     │
│   lock:3, 500ms)    │            │   lock:3, 500ms)    │
└────────┬───────────┘            └────────┬───────────┘
         │ 成功                            │ 超时（A 持有锁）
         ▼                                 ▼
┌────────────────────┐            ┌────────────────────┐
│ 重读 DB:            │            │ skip 司机 3         │
│ driver.status ==    │            │ tryLock(driver:     │
│ ONLINE_IDLE? YES    │            │   lock:7, 500ms)    │
└────────┬───────────┘            └────────┬───────────┘
         ▼                                 ▼
┌────────────────────┐            ┌────────────────────┐
│ assignDriver()      │            │ 成功 → 重读 DB →    │
│ driver.status = BUSY│            │ assignDriver(司机7) │
│ order.status =      │            └────────────────────┘
│   DRIVER_ASSIGNED   │
└────────┬───────────┘
         ▼
┌────────────────────┐
│ 记录事件:            │
│ DRIVER_ASSIGNED     │
│ 释放 driver:lock:3  │
│ 释放 order:lock:A   │
└────────────────────┘
```

**安全保障**：
1. 锁顺序 100% 统一（order → driver）→ 无循环等待 → **无死锁**
2. tryLock 500ms 超时 → 不无限等待 → **无活锁**
3. 加锁后重读 DB → 防止 ABA 竞态 → **无重复分配**
4. 所有候选失败 → 记录 ORDER_ASSIGN_FAILED → **明确告知调用方**

**压测结果**：100 订单 × 20 司机，零重复分配、零丢失、零死锁。

## 七、面试讲解提示

**白板画图顺序**（面试时边画边讲）：

1. 先画四层（横线分隔）—— "这个系统分四层"
2. 在调度层画 ScoringEngine 和两个实现—— "评分引擎是可插拔的"
3. 在调度层画锁的流程—— "二阶锁保证并发安全"
4. 在数据层画 order_event —— "事件溯源记录一切"
5. 在观测层画三个组件—— "三层可观测性"

**不要**：一次性画完再讲——面试官跟不上。
**要**：画一层讲一层，每个设计点讲"为什么"。
